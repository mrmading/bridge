BRIDGE

A desktop client for Claude Code.

It reads ~/.claude directly and drives the real claude CLI, so your hooks, skills, agents and sessions stay exactly where they are. Not a reimplementation: a session started in Bridge is an ordinary Claude Code session you can pick up in the terminal.

Drag it into Applications and open it. Bridge checks for the two free tools it needs and offers to install whatever is missing. First launch: macOS blocks it once, then System Settings → Privacy & Security → Open Anyway. Notarised builds are coming.

What you get

Chat, not a terminal log

Streaming text, thinking folded behind one line, and every tool call as a card: Bash shows its output, Edit renders a real ± diff, sub-agents get their own gutter.

Sessions are tabs

Several at once, each with its own transcript, tokens, cost and working directory. A tab that is working flashes green. Keep typing while it runs and the message queues, like the terminal.

⌘F finds anything you ever ran

Describe it in your own words. Bridge greps every transcript on the machine, ranks on how many of your terms a session actually covers, and shows what you asked, how it ended, and the matching lines.

Your config, editable

CLAUDE.md, settings, memory files, skills and agents in one place. ⌘S writes to disk. Markdown gets a split editor with a live preview.

A live activity log

What is running now, turns and spend today, and every start, finish, failure, interrupt and file save, each naming the session that caused it.

A real macOS app

./mac/build.sh produces Bridge.app: a Swift shell around a WKWebView that starts the bundled server and shows it in a native window. No Electron, no Chromium.

How it works

One Bun file, zero dependencies, three jobs.

  1. Reads ~/.claude, read-only. Transcripts are normalized into a flat event list, tool results joined back onto their tool_use_id, usage de-duplicated by request. Metadata is cached by mtime, so hundreds of transcripts list in about 20 ms.
  2. Spawns the real CLI per turn with --output-format stream-json and --session-id / --resume, streaming stdout to the browser over SSE. Your settings.json env is injected so hooks behave identically.
  3. Searches with ripgrep, one pass per term in parallel, scoring on term coverage rather than raw hit count.

Safety

Bridge does not expose your machine.

Every file API is confined to the folders you add in the Directory panel, and inside those it still refuses anything matching .ssh, .aws, .gnupg, .credentials, .env*, *.pem or id_rsa — reads and writes alike. Anything outside says so and offers to add the folder. The composer defaults to acceptEdits; bypassPermissions has to be chosen explicitly. The server binds to localhost only.
